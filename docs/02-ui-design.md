# 02. UI 구현 지침

> 목적: 화면의 모양, 문구, 화면 크기별 배치를 고정한다. UI는 사용자가 보고 누르는 화면을 뜻한다. 기능 범위는 [PRD](../PRD.md), 동작은 [프런트엔드 지침](03-frontend-behavior.md)을 함께 따른다.

## 1. 참고 이미지에서 가져올 특징

2026-11-10에 [사용자가 제공한 Pinterest 이미지](https://kr.pinterest.com/pin/820710732109005535/)를 직접 확인했다. 원본은 여러 모바일 화면을 한 장에 모은 장난감·캐릭터 카탈로그 시안이다.

| 원본에서 관찰한 특징 | 마음결에 적용할 방법 |
|---|---|
| 분홍·보라·민트·노랑·파랑의 넓은 파스텔 색면 | 입력 안내와 감성 결과 카드에 파스텔 배경 사용 |
| 모서리가 크게 둥근 모바일 화면과 카드 | 주요 카드 28px, 입력창 20px 모서리 적용 |
| 중앙에 크게 배치한 입체 동물 캐릭터 | 자체 제작한 CSS 곰 캐릭터를 결과 카드 위쪽에 배치 |
| 흰색 또는 밝은 알약 모양 버튼 | 예시·지우기 버튼에 밝은 배경과 둥근 모서리 적용 |
| 큰 제목과 짧은 설명, 넓은 간격 | 입력·결과·이유를 명확한 순서로 배치 |

아래의 색상 코드, 서비스명, 화면 배치와 치수는 이 프로젝트를 위한 **새로운 설계값**이다. 원본의 정확한 수치를 추출한 값이 아니다. 원본에 있는 쇼핑·캐릭터 선택·즐겨찾기·재생·메뉴 기능은 구현하지 않는다. 검은색은 원본 시안을 놓은 바탕이므로 실제 서비스 배경으로 사용하지 않는다.

원본 이미지나 동물 캐릭터를 잘라 사용하거나 외부 이미지 주소를 화면에 직접 연결하지 않는다. 직접 만든 CSS 도형으로 분위기를 구현한다. 외부 이미지 다운로드, 이미지 생성 API, 3D 라이브러리는 이 프로젝트의 실행 의존성에 포함하지 않는다.

## 2. 화면의 고정 구성

서비스명은 **마음결**이다. 한국어 단일 페이지이며 경로는 `/` 하나다.

```text
┌──────────────────────────────────────────────────────────┐
│ 마음결                                  텍스트 감성 분석 │
│                                                          │
│ 문장의 분위기를 읽어요                                    │
│ 짧은 글을 남기면 긍정·부정·중립으로 살펴드려요.            │
│                                                          │
│ ┌─ 입력 카드 ─────────────────┐ ┌─ 결과 카드 ──────────┐ │
│ │ 분석할 문장                 │ │     CSS 곰 캐릭터    │ │
│ │ [여러 줄 입력창]            │ │   긍정 / 부정 / 중립  │ │
│ │ 도움말          0 / 2,000자  │ │ 신뢰도 87% + 막대     │ │
│ │ [기쁜 문장][아쉬운 문장]     │ │ 분석 이유             │ │
│ │ [담담한 문장]               │ │ 짧은 설명             │ │
│ │ 개인정보·전송 안내          │ │ 신뢰도 설명            │ │
│ │ [감성 분석하기] [지우기]     │ │ 필요 시 저장 실패 안내 │ │
│ └─────────────────────────────┘ └───────────────────────┘ │
│ 문장의 표현을 분류하는 참고 정보이며 심리 진단이 아니에요. │
└──────────────────────────────────────────────────────────┘
```

그림의 `87%`와 결과는 배치를 설명하기 위한 예시다. 최초 방문 화면에는 실제 분석 결과, 신뢰도 숫자, 이유를 미리 표시하지 않는다.

### 데스크톱·태블릿: 화면 너비 768px 이상

- 내용 영역은 `max-width: 1120px`, 좌우 여백은 최소 24px, 중앙 정렬한다.
- 헤더 높이는 최소 64px, 소개 영역 아래 간격은 32px다.
- 본문은 CSS Grid 두 열, `minmax(0, 1.1fr) minmax(0, 1fr)`, 열 간격 24px다.
- 카드 내부 여백은 32px, 결과 카드 최소 높이는 440px다. 내용이 늘어나면 자연스럽게 높이가 늘어나야 한다.
- 768~1023px에서는 카드 내부 여백 24px, 열 간격 16px로 줄인다.
- 입력창 높이는 최소 220px, 세로 크기 조절을 허용한다. 가로 크기 조절은 허용하지 않는다.

### 모바일: 화면 너비 768px 미만

- 좌우 여백 16px, 헤더 아래 24px, 카드 간격 20px다.
- 입력 카드 → 결과 카드 순서로 한 열로 쌓는다. DOM 순서도 동일하게 유지한다.
- 카드 내부 여백 20px, 모서리 24px, 결과 카드 최소 높이 360px다.
- 입력창 최소 높이는 180px다. 주요 분석 버튼은 한 줄 전체 너비, 지우기는 그 아래에 둔다.
- 예시 버튼은 줄바꿈을 허용한다. 가로 스크롤 목록으로 만들지 않는다.
- 콘텐츠 전체 높이를 고정하거나 화면 높이만큼 잘라내지 않는다. 모바일 키보드가 열려도 입력창과 제출 버튼에 스크롤로 접근할 수 있어야 한다.

## 3. 디자인 토큰

디자인 토큰은 여러 곳에서 공통으로 사용하는 색상·간격의 이름이다. `public/css/styles.css`의 `:root`에 선언한다. 같은 의미에 새로운 색을 임의로 추가하지 않는다.

```css
:root {
  --color-page: #F7F4FC;
  --color-surface: #FFFFFF;
  --color-text: #292336;
  --color-muted: #665D75;
  --color-primary: #7650B3;
  --color-primary-hover: #624098;
  --color-border: #D9D1E5;
  --color-control-border: #8A7D9B;
  --color-focus: #513178;
  --color-positive-bg: #DDF4E8;
  --color-positive-text: #24553F;
  --color-negative-bg: #FBE4DF;
  --color-negative-text: #7A3E37;
  --color-neutral-bg: #E3EDFA;
  --color-neutral-text: #35527A;
  --color-welcome-bg: #ECE2FC;
  --color-error-bg: #FFF0ED;
  --color-error-text: #8E3028;
  --radius-card: 28px;
  --radius-input: 20px;
  --radius-pill: 999px;
  --shadow-card: 0 12px 32px rgb(58 37 86 / 8%);
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 24px;
  --space-6: 32px;
}
```

| 요소 | 고정 스타일 |
|---|---|
| 글꼴 | `"Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif`; 외부 폰트 요청 없음 |
| 본문 | 16px, 굵기 400, 줄 높이 1.6 |
| 보조 문구 | 14px, 줄 높이 1.5, `--color-muted` |
| 메인 제목 | 데스크톱 40px / 모바일 30px, 굵기 700, 줄 높이 1.25 |
| 카드 제목 | 20px, 굵기 700 |
| 결과 감성명 | 28px, 굵기 700 |
| 신뢰도 숫자 | 36px, 굵기 700, 숫자 폭 고정 `font-variant-numeric: tabular-nums` |
| 주요 버튼 | 높이 최소 48px, 좌우 패딩 24px, 보라 배경·흰 글자 |
| 보조·예시 버튼 | 높이 최소 44px, 좌우 패딩 16px, 밝은 배경·어두운 글자 |
| 입력창 | 16px 본문, 안쪽 여백 16px, 1px `--color-control-border` 테두리, 흰 배경 |
| 포커스 | `outline: 3px solid var(--color-focus); outline-offset: 3px` |
| 신뢰도 막대 | 높이 10px, 둥근 끝, 채움 너비는 검증된 신뢰도 수치와 동일 |

작은 흰색 글자를 파스텔 배경 위에 놓지 않는다. 실제 렌더링에서 일반 글자 명암비 4.5:1 이상, 큰 글자·조작 요소 경계 및 포커스 표시는 3:1 이상을 확인한다. `--color-border`는 장식적인 카드 구분선에만 사용하고, 입력창처럼 경계가 필요한 조작 요소에는 `--color-control-border`를 쓴다.

위 색상값의 명암비 계산상 주요 버튼은 약 5.88:1, 보조 문구와 흰 배경은 약 6.20:1, 긍정·부정·중립의 지정 글자색과 배경색 조합은 각각 약 7.43:1·6.71:1·6.73:1이다. 구현에서 투명도를 낮추거나 배경을 바꾸면 다시 측정한다.

## 4. 캐릭터 구현

CSS 곰은 결과 영역의 장식이다. 원형 귀 두 개, 둥근 얼굴, 작은 눈 두 개, 코, 입으로 구성하고 고유한 이름·설정·대화 기능은 추가하지 않는다.

- 크기: 데스크톱 160×160px, 모바일 128×128px의 고정 장식 영역 안에 배치한다.
- 색: 크림색 얼굴에 밝은 부분과 약한 그림자를 넣어 입체감을 표현한다. 감성에 따라 얼굴색 전체를 강한 빨강으로 바꾸지 않는다.
- 최초·입력 중: 평온한 기본 표정. 분석 중: 같은 표정과 별도의 작은 로딩 표시.
- 긍정: 웃는 입, 부정: 약하게 내려간 입, 중립: 수평 입. 결과 감성명도 반드시 함께 표시한다.
- 오류: 결과 감성 표정으로 바꾸지 않고 기본 표정을 사용한다. 오류를 부정 감성으로 표현하지 않는다.
- 캐릭터 DOM에는 `aria-hidden="true"`를 지정한다. 결과 의미는 실제 텍스트가 전달한다.
- 외부 이미지가 없어도 형태가 완성되어야 한다. 복잡한 3D 모델이나 반복적인 튀기 애니메이션을 만들지 않는다.

## 5. 상태별 화면

| 상태 | 입력 영역 | 결과 영역 |
|---|---|---|
| 최초 `idle` | 빈 입력창, `0 / 2,000자` | 기본 캐릭터, “어떤 분위기가 담겨 있을까요?”, 짧은 입력 안내 |
| 입력 중 `editing` | 입력과 글자 수 반영 | 최초 안내. 이전 결과·오류는 숨김 |
| 분석 중 `loading` | 읽기 전용 입력창, 버튼 모두 비활성 | “문장의 분위기를 살펴보고 있어요…”와 로딩 표시, 수치 없음 |
| 성공 `success` | 현재 입력 유지, 버튼 활성 | 해당 감성명·신뢰도·막대·분석 이유 표시 |
| 실패 `error` | 입력 유지, 버튼 활성 | 오류 안내. 감성명·신뢰도·분석 이유는 표시하지 않음 |

성공 카드 배경은 긍정=민트, 부정=피치, 중립=하늘색이다. 로딩·기본 상태는 연보라색이다. 색만으로 상태를 구분하지 않는다.

입력 오류는 입력창 아래에 표시하고 입력창에 `aria-invalid="true"`를 설정한다. 네트워크·서버 오류는 결과 영역에 표시한다. 같은 오류를 두 곳에서 중복 안내하지 않는다. 오류 문구와 재시도 가능 여부는 [API·AI 계약](04-api-ai-contract.md)이 기준이다.

DB 저장 실패는 분석 실패가 아니다. 성공 결과 아래에 작은 안내만 추가하고, 결과를 숨기거나 자동 재요청하지 않는다.

## 6. 화면 문구

| 위치 | 사용할 문구 |
|---|---|
| 브랜드 | 마음결 |
| 헤더 보조 | 텍스트 감성 분석 |
| 제목 | 문장의 분위기를 읽어요 |
| 소개 | 짧은 글을 남기면 긍정·부정·중립으로 살펴드려요. |
| 입력창 레이블 | 분석할 문장 |
| 입력창 예시 문구 | 예: 오늘 친구와 오랜만에 만나서 정말 즐거웠어요. |
| 입력 도움말 | 앞뒤 공백을 제외하고 1~2,000자까지 입력할 수 있어요. |
| 분석 버튼 | 감성 분석하기 |
| 분석 중 버튼 | 분석 중… |
| 초기화 버튼 | 지우기 |
| 예시 버튼 | 기쁜 문장 / 아쉬운 문장 / 담담한 문장 |
| 최초 결과 제목 | 어떤 분위기가 담겨 있을까요? |
| 최초 결과 설명 | 문장을 입력하고 감성 분석하기를 눌러보세요. |
| 로딩 | 문장의 분위기를 살펴보고 있어요… |
| 성공 소제목 | 분석 결과 / 신뢰도 / 분석 이유 |
| 신뢰도 설명 | AI가 스스로 추정한 확신 정도예요. 정답 확률이나 검증된 정확도가 아니에요. |
| 저장 실패 | 분석은 완료했지만 운영 기록을 저장하지 못했어요. |
| 재시도 버튼 | 다시 시도 |
| 하단 안내 | 문장의 표현을 분류하는 참고 정보이며 심리 진단이 아니에요. |

입력창과 제출 버튼 사이에 다음 안내를 항상 표시한다. 접힌 영역이나 마우스 전용 도움말 안에 숨기지 않는다.

> 입력한 문장은 분석을 위해 OpenAI로 전송돼요. 우리 서비스 DB에는 원문과 분석 이유를 저장하지 않아요. 이름·연락처 등 개인정보는 입력하지 마세요.

전송·저장에 대한 상세 기준은 [DB·보안 지침](05-database-security.md)을 따른다. “어디에도 저장되지 않는다”와 같은 문구로 바꾸지 않는다.

위 상시 안내 바로 아래에 HTML `<details>`와 `<summary>데이터 처리 안내</summary>`를 둔다. 처음에는 접혀 있으며 05 문서의 펼친 설명과 OpenAI 데이터 정책 링크를 담는다. 별도 모달이나 동의 체크박스는 추가하지 않는다.

## 7. 접근성과 움직임

- HTML에 `lang="ko"`, 뷰포트 메타 태그, 페이지 제목 `마음결 | 텍스트 감성 분석`을 설정한다.
- `header`, `main`, `form`, `section`, `footer`를 의미에 맞게 사용한다. 메인 `h1`은 하나다.
- 입력창에 눈에 보이는 `<label>`을 연결한다. 도움말·글자 수·입력 오류의 ID를 `aria-describedby`로 연결한다.
- 버튼은 실제 `<button>`으로 구현한다. 예시·지우기·재시도는 `type="button"`, 제출만 `type="submit"`이다.
- 키보드 Tab 순서는 입력창 → 예시 3개 → 데이터 처리 안내(펼치면 정책 링크 포함) → 분석 → 지우기 → 오류 시 재시도 순서다. 장식에는 포커스를 주지 않는다.
- 결과 컨테이너는 로딩 중 `aria-busy="true"`다. 로딩 안내는 `role="status"` 또는 `aria-live="polite"`로 알린다.
- 성공 시 결과 제목에 `tabindex="-1"`를 두고 포커스를 이동한다. 오류는 `role="alert"`로 알린다. 동일 문장을 여러 live region에서 중복 낭독하지 않는다.
- 신뢰도 막대는 장식으로 `aria-hidden="true"` 처리하고, “신뢰도 87%”처럼 숫자와 설명을 실제 텍스트로 읽을 수 있게 한다.
- 전환은 색·투명도에 한해 150~200ms다. `prefers-reduced-motion: reduce`에서는 전환과 로딩 회전을 끄고 “분석 중…” 텍스트는 유지한다.
- 긴 단어·URL·이유는 `overflow-wrap: anywhere`로 줄바꿈한다. 확대를 막는 뷰포트 설정은 사용하지 않는다.

## 8. 완료 기준과 검증

- [ ] 360×800, 768×1024, 1440×900 화면에서 가로 스크롤·잘린 버튼·겹친 텍스트가 없다.
- [ ] 767px는 한 열, 768px는 두 열로 바뀌며 입력 카드가 항상 먼저 나온다.
- [ ] 처음 열었을 때 성공 결과나 임의의 신뢰도 값이 없다.
- [ ] 긍정·부정·중립·로딩·입력 오류·서버 오류·DB 저장 실패를 각각 확인했다.
- [ ] 캐릭터가 원본 이미지 요청 없이 표시되고 기능 없는 메뉴·하트·재생 버튼이 없다.
- [ ] 키보드만으로 입력·예시 선택·분석·초기화·재시도를 수행할 수 있다.
- [ ] 스크린리더에서 입력 레이블, 분석 중 안내, 감성명, 신뢰도, 이유, 오류를 이해할 수 있다.
- [ ] 본문 200% 확대에서도 기능과 텍스트가 사라지지 않는다.
- [ ] 파스텔 배경의 일반 글자 대비 4.5:1, 포커스 대비 3:1 이상을 측정했다.

검증 결과와 화면 캡처의 기록 방법은 [테스트·배포 지침](06-testing-deployment.md)을 따른다.
